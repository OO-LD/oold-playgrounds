# Wheels vendored into the site so a cold start never reaches files.pythonhosted.org.
#
# micropip resolves a name against the Pyodide distribution lock first, then against the
# piplite indexes, then against PyPI. These are the distributions in the closure of the
# kernel bootstrap and of what oold_agent.setup() installs that the Pyodide distribution
# does not carry. Everything already in the distribution is deliberately absent here:
# vendoring it would ship bytes the CDN serves anyway, and a compiled artifact cannot
# come from PyPI at all.
#
# comm is in the list for the kernel, not for oold. jupyterlite-pyodide-kernel bundles
# pyodide-kernel but not its dependencies, and without comm the kernel never reaches
# kernel_info_reply when PyPI is unreachable.
#
# Regenerate after changing oold_agent.REQUIREMENTS or bumping the pyodide kernel:
#
#   .venv/Scripts/python.exe scripts/resolve_wheels.py resolve \
#     --pyodide-version "$(.venv/Scripts/python.exe -c 'from jupyterlite_pyodide_kernel.constants import PYODIDE_VERSION; print(PYODIDE_VERSION)')" \
#     --cache .cache --agent contents/oold_agent.py \
#     --bundled .venv/share/jupyter/labextensions/@jupyterlite/pyodide-kernel-extension/static/pypi
#
# scripts/build.sh verifies the staged set against the lock on every build, so a stale
# list fails there rather than silently going back to PyPI at runtime.
